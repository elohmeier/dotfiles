# Web Usability

Use this reference for websites, web apps, product pages, navigation, content-heavy interfaces, mobile web, and low-cost usability evaluation.

## How People Use Web Interfaces

Most users scan, sample, and choose the first plausible path. They often do not read instructions, compare every option, or build a complete understanding before acting. Design pages as usable sign systems, not as documents that must be read top to bottom.

Implications:

- Make the main purpose of each page obvious.
- Make primary actions visually and verbally clear.
- Put important words at the start of headings, links, and labels.
- Prefer familiar patterns where novelty does not create value.
- Remove text that exists only to explain avoidable confusion.
- Design for quick recovery when users choose a merely plausible path.

## Page Clarity

A useful page answers:

- Where am I?
- What can I do here?
- What is most important?
- Where can I go next?
- What changed after my action?

If the page needs a paragraph to explain itself, fix labels, grouping, hierarchy, or flow first.

## Navigation

Navigation should work like signs in a place.

- Use stable locations for global navigation.
- Use current-state indicators.
- Group navigation by user goals, not org structure.
- Keep names short, specific, and mutually distinct.
- Use breadcrumbs when hierarchy matters.
- Make search visible when users know what they want but not where it lives.
- Avoid hiding important navigation behind low-discoverability controls on large screens.

## Links, Buttons, And Choices

- Links navigate; buttons perform actions.
- Link text should make sense out of context.
- Choices should be mindless when the domain allows it: clear categories, few competing options, obvious defaults.
- Use progressive disclosure for advanced paths, but do not hide frequent or high-value tasks.
- Avoid clever wording when users are deciding under uncertainty.

## Content

- Omit words that do not help users decide, act, or understand consequences.
- Replace instructions with better UI when possible.
- Use headings, bullets, tables, and examples for scanning.
- Put policy/legal detail behind summaries when permitted, but do not hide material consequences.
- Write error and empty-state copy as part of the workflow, not as afterthoughts.

## Mobile Web

- Prioritize tasks, not desktop parity.
- Keep touch targets large enough and separated.
- Make forms resilient to virtual keyboards, autofill, paste, and narrow screens.
- Avoid sticky UI that crowds the viewport.
- Test real devices for scrolling, input, focus, zoom, and orientation.

## Lightweight Usability Testing

Frequent small tests are usually more valuable than rare formal studies.

Use:

- Representative tasks.
- Three to five participants per round for qualitative discovery.
- Think-aloud observation.
- Realistic data.
- Notes on hesitation, misclicks, misunderstood labels, and recovery.

Avoid turning tests into opinion surveys. What users do is usually more diagnostic than what they say they prefer.
