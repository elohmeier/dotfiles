# Interface Craft

Use this reference for concrete UI execution: layout, hierarchy, typography, controls, color, depth, imagery, and visual finish.

## Start With The Feature

Design the core task before designing the shell. A navigation frame, dashboard grid, or settings taxonomy should follow from the features and workflows it must support.

Start by defining:

- The user goal.
- The primary object or data.
- The main action.
- The critical state changes.
- The failure and empty states.

## Hierarchy

Hierarchy is how the interface tells users what matters.

Use:

- Size, weight, contrast, spacing, position, and alignment.
- De-emphasis for supporting metadata.
- Fewer competing emphases.
- Clear grouping before decorative separation.

Do not rely on semantic document hierarchy alone. Visual hierarchy must match task priority.

## Spacing And Layout

Spacing communicates relationships.

- Use a small spacing scale and repeat it consistently.
- Put related items closer together than unrelated items.
- Avoid ambiguous gaps that make users guess which label or control belongs to which group.
- Leave enough room for actual content, translations, validation messages, and user-generated values.
- Do not fill space just because it exists.

## Typography

- Use a limited type scale.
- Keep readable body sizes and line lengths.
- Use weight and size for hierarchy before adding extra colors.
- Align text for scanning and comparison.
- Keep labels near controls and values.
- Avoid all caps for long labels or content.

## Color

Color should carry roles, not decoration alone.

Define:

- Neutral text and surfaces.
- Primary action.
- Focus.
- Selection.
- Success.
- Warning.
- Error.
- Disabled.
- Informational states.

Never rely on color alone. Pair color with label, icon, shape, position, or pattern.

## Controls

- Use the control that matches the input: checkbox for independent binary choices, radio/segmented control for small exclusive sets, select/combobox for larger sets, slider for approximate continuous values, numeric field for precise numbers.
- Make the whole control target clickable where possible.
- Avoid custom controls unless they improve the task enough to justify extra learning and accessibility work.
- Put destructive actions away from routine confirmation paths.
- Show disabled reasons and enablement paths.

## Depth And Layers

Use depth to explain stacking, elevation, modality, and focus. Shadows, borders, overlays, and background changes should clarify interaction state.

Avoid layering that makes users wonder whether background content is still interactive.

## Images And User Content

- Use images at their intended size and crop.
- Maintain text contrast on images.
- Plan for missing, low-quality, oversized, and user-uploaded media.
- Do not let long names, unbroken strings, or empty values break layout.

## Finish

Polish is not ornament. It is the removal of friction and ambiguity.

Check:

- Empty states.
- Loading and skeleton states.
- Error density.
- Hover, active, focus, selected, disabled.
- Long text and localization.
- Keyboard navigation.
- Mobile wrapping.
- High contrast and reduced motion.
